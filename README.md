# movie-mode

**RDP越しにDiscordの画面共有をすると画質が落ちる問題**を解決するツール。

セッションを物理コンソールへ移し、GPUが描画する本来のデスクトップを
Discordにキャプチャさせる。**配信を張ったまま移行できる**ので、視聴者側の映像は途切れない。

Windows専用。追加パッケージ不要（PowerShell + Python標準ライブラリ + Windows同梱の `csc.exe`）。

---

## 何が問題なのか

サーバー機にRDPで接続し、**その機械のDiscord**から画面共有をしている場合、
配信経路にRDPは入っていない。それでも画質が落ちる。理由はこうだ。

**RDPは「Discordがキャプチャするデスクトップそのもの」を作り替えてしまう。**

| | RDPセッション | コンソールセッション |
|---|---|---|
| 描画アダプタ | Microsoft Remote Display Adapter | 実際のGPU |
| 解像度 | RDPクライアント窓のサイズに追従（例: 1692x911） | モニタのネイティブ解像度 |
| 取り込み | ソフトウェアアダプタ経由・フレームレート上限あり | GPUのDesktop Duplication |

解像度が中途半端な値になると、

```
ソース 1280x720 → 1692x911 に拡大 → Discord が 1920x1080 へ再スケール
```

と**非整数スケーリングが2回**入り、エンコード前の時点でディテールが溶ける。
さらにRDPセッションは取り込みフレームレートにも上限がかかる。

RDPを別のリモートツールに変えても直らない。**セッションの種別そのものを変える必要がある。**

## 使い方

### 1. ビルド

```bash
build.cmd
```

Windows同梱の `csc.exe` を使うので、Visual Studioもコンパイラのインストールも要らない。
`MovieMode.exe` と `Setup.exe` が生成される。

リリースのZIPにはビルド済みのものが入っているので、この手順は省略できる。

### 2. セットアップ

`Setup.exe` を実行する。以下をまとめて行う。

- リモコンをログオン時に**昇格状態で常駐**登録（これが無いとブラウザから切り替えできない）
- ファイアウォールで TCP 8900 の受信を許可
- デスクトップとスタートメニューにショートカットを作成（`Ctrl + Alt + M`）

項目はチェックボックスで個別に外せる。同じ画面から**アンインストール**もできる。

リモコンを使わず、この機械の上だけで完結させるなら省略しても構わない。

### 3. 実行

```
1. 配信したいものを再生し、Discordで画面共有を開始する    ← 必ず先に
2. MovieMode.exe を起動（UACを承認）
3. 「映画モードにする」を押す
4. RDPが切断される。配信はそのまま継続
5. 見終わったら普通にRDPで繋ぎ直す（元の状態に戻る）
```

**2と3の順番が逆だと詰む。** 移動後は画面共有を開始する操作手段が無い。

GUIには現在のセッション種別・解像度・描画アダプタ・NVENCの稼働状況が表示される。
「事前チェック」を押すと、移動せずに設定だけ検証できる。

### 3. リモコン（任意）

映画モードに入るとその機械を直接操作できなくなるため、
LAN内の別端末から再生を制御できるWebリモコンを同梱している。

```bash
Movie-Remote.cmd
```

起動するとURLが表示される。スマホやほかのPCのブラウザで開くと、
再生/一時停止・シーク・音量・全画面のボタンが並ぶ。

**ブラウザから「映画モードにする」も実行できる。**
ただし単発起動（`Movie-Remote.cmd`）では不十分で、常駐登録が必要になる。理由は2つ。

1. `movie-mode.ps1` はリモコンを「移行処理の一部として」起動する。
   つまり**映画モードに入る前はリモコンが動いていない**ので、
   リモコンから映画モードを開始することができない
2. `tscon` はSYSTEM権限を要求するため、リモコン自身が昇格状態で
   動いていないとセッションを切り替えられない

常駐登録は `Setup.exe` が行う（中身は `install-autostart.ps1`）。
コマンドラインから直接実行することもできる。

```bash
powershell -ExecutionPolicy Bypass -File install-autostart.ps1
powershell -ExecutionPolicy Bypass -File install-autostart.ps1 -Uninstall
```

UACは実行時の1回だけ。

登録後は、他の端末のブラウザで `http://<このPCのLAN IP>:8900/?t=<トークン>` を開けば、
セッション切り替えと再生操作の両方ができる。
URLは GUI の「リモコンを開く」を押すとログに表示され、クリップボードにもコピーされる。

## 中身

| ファイル | 用途 |
|---|---|
| `MovieModeGui.cs` | 本体GUI（WinForms） |
| `SetupGui.cs` | セットアップGUI |
| `movie-mode.ps1` | セッション移動の処理本体 |
| `movie-remote.py` | Webリモコン兼セッション切り替えAPI |
| `install-autostart.ps1` | 常駐登録・ファイアウォール・ショートカット（Setup.exeの実処理） |
| `check-stream.ps1` | 状態の実測（NVENC・解像度・Discord負荷） |
| `build.cmd` | `csc.exe` で両exeをビルド |
| `movie-mode.manifest` / `setup.manifest` | `requireAdministrator` を要求するマニフェスト |

`Setup.exe` は処理を持たず、`install-autostart.ps1` を呼んで出力を表示するだけの薄い層。
同じ処理を二重に実装すると片方が腐るため、スクリプト側を唯一の実装にしている。

### コマンドラインオプション

```bash
MovieMode.exe                            # GUI
powershell -File movie-mode.ps1 -Yes     # 確認なしで即実行
powershell -File movie-mode.ps1 -DryRun  # 移動せず事前チェック
powershell -File movie-mode.ps1 -RestartDiscord  # 移動後にDiscordを再起動
powershell -File movie-mode.ps1 -NoRemote        # リモコンを起動しない
```

`-RestartDiscord` は既定OFF。**付けると配信が切れて張り直しが必要**になる。
移動後に映像が固まる・黒くなる場合だけ使う。

## 仕組み

`tscon <セッションID> /dest:console` でセッションをコンソールへ移す。
これはSYSTEM権限を要求するため、schtasksでSYSTEMとして動くタスクを作って実行している。

Discordを再起動しないのが要点。既存のキャプチャセッションはデスクトップの
切り替わりを跨いで生き残るため、配信を止めずに移行できる。

## 注意

### 移行後にRDPで繋ぎ直すと元に戻る

Windowsの仕様で、RDP接続はセッションを仮想画面側へ引き戻す。
**配信中はRDPで入らないこと。** 制御が必要ならリモコンを使う。

### ブラウザのハードウェアアクセラレーション

DRM保護された動画を配信サービスで再生している場合、コンソールセッションでは
GPUが効くためハードウェアDRM経路に入り、**画面共有が黒画面になることがある**。
その場合はブラウザ側でハードウェアアクセラレーションを無効にする
（ソフトウェア経路になり、解像度の上限と引き換えにキャプチャできるようになる）。

起動時に検査して警告するが、Chromiumは明示的にOFFにしたときしか設定を書き込まないため、
「判定不能」と出ることがある。確実に見るならブラウザの設定画面で確認すること。

### モニタの電源

物理モニタの電源を切るとGPUがディスプレイ切断とみなし、解像度が落ちることがある。
繋いだまま電源も入れておくか、HDMIダミープラグ（EDIDエミュレータ）を使う。

### リモコンをLANに開くことについて

リモコンは `0.0.0.0:8900` で待ち受け、キー送信とセッション操作を受け付ける。
起動時に生成されるトークンをURLに含めないと操作できないが、
**信頼できないネットワークでは動かさないこと。**
`--no-token` を付けると認証なしになる（非推奨）。

### `mstsc /shadow` について

移行後もリモートから操作する手段として、RDPシャドウ接続
（`mstsc /v:<ホスト名> /shadow:<ID> /control`）を使えるようポリシーを設定する処理が入っている。
ただしこれはRDS（サーバーOS）向けの機能で、クライアントSKUでは動作しないことがある。
IPアドレスは受け付けず、ホスト名にアンダースコアが含まれると
「このコンピューター名は無効です」で失敗する（DNS的に不正な文字のため）。

動かない環境では、代わりにリモコンを使うか、
セッションを奪わないミラー型のリモートツール（Parsec / RustDesk / Sunshine など）を検討する。
